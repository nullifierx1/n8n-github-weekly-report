# Недельный отчёт GitHub

Практика 8 курса «Технологии ИИ в разработке ПО». Выберите понедельник, чтобы увидеть сводку за неделю по `nullifierx1/n8n-code-review-test`. Интерфейс показывает четыре счётчика, разбивки по типам и авторам созданных Issues и сравнение с предыдущей неделей. Даты считаются по UTC.

Фронтенд использует React, TypeScript, Vite и Tailwind CSS. Кнопка, поле, подпись, карточки и сообщения об ошибках взяты из библиотеки **shadcn/ui**. Цвета, шрифт и скругления заданы в [теме](src/style.css).

## Запуск

Требуются Node.js 22.12 или новее, npm и GNU Make. Визуальные эталоны проверены на Linux, включая WSL.

```bash
make setup
make run
```

Команда `make setup` устанавливает зависимости и Chromium для Playwright. `make run` запускает Vite и выводит локальный адрес. Для сборки используйте `make build`. Список команд доступен через `make help`.

### Подключение n8n

1. Импортируйте [workflow](n8n/weekly-report-api.json) в n8n. В Webhook выберите Header Auth credential с полем `X-Report-Token`. Публичный репозиторий читается через GitHub Search API. Если нужна большая частота запросов, подключите GitHub credential на HTTP-нодах.
2. Опубликуйте workflow и скопируйте **Production URL** из Webhook. Скопируйте `.env.example` в `.env.local`. Укажите URL и значение header credential.
3. Перезапустите Vite. Браузер обращается к `/api/weekly-report`, Vite проксирует запрос в n8n. Переменные с URL и credential остаются на сервере Vite. При размещении статической сборки настройте проксирование отдельно.

Этот экспорт даёт отдельный веб-вход к отчёту по данным GitHub. Имеющийся workflow 7.2 с Cron, Gmail и Data Table работает независимо. Веб-версия считает предыдущую неделю по GitHub и читает до 100 созданных Issues для разбивок. При неполном ответе GitHub она завершает запрос ошибкой.

Для демонстрации выберите `2026-11-16` (счётчики 8 / 4 / 7 / 1) и `2026-11-09` (пустая неделя). [Спецификация и JSON-контракт](spec.md).

## Тесты

```bash
make check
make test-report
```

`make check` собирает приложение и запускает все клиентские тесты. Чтобы запустить только тесты, используйте `make test`. Playwright сам запускает Vite. Для тестов webhook и credentials не нужны. Тесты проверяют форму, валидацию, загрузку и повторную отправку, пустую неделю, ошибку и повтор запроса, полный путь до отчёта и вид готового отчёта на двух размерах экрана. Для пустых данных и ошибки есть отдельные мобильные эталоны.

Визуальные эталоны с системным шрифтом привязаны к платформе и версии Chromium. На другой ОС используйте `npm test -- tests/report.spec.ts` для проверок поведения и снимите отдельные визуальные эталоны после просмотра отличий.

## Прототип и AI

[PDF-экспорт макета](prototype/weekly-report.pdf) можно открыть прямо на GitHub. В нём показаны шесть состояний сценария и мобильный экран. [HTML-прототип](prototype/report.html) можно скачать и открыть в браузере. Переключатель внизу показывает все состояния, в том числе загрузку и ошибку. Прототип создан с помощью Codex, при доработке использован референс из каталога v0. [Shadcn Dashboard](https://v0.app/templates/Pf7lw1nypu5) Он доступен локально как самостоятельный HTML-файл.

Сокращённые постановки, использованные в работе:

- **Прототип.** Сделать экран недельного отчёта и показать исходное состояние, ввод, загрузку, успех, пустые данные и ошибку. Уложить карточки в две колонки на узком экране.
- **Реализация.** Взять формы и карточки из shadcn/ui, перенести согласованные состояния в React и подключить запрос по JSON-контракту.
- **Тесты.** Воспроизвести основной путь и задержку через Playwright. Повторить отправку до ответа и посчитать запросы.

При переносе прототипа в код добавлены отдельные сообщения о валидации и данные сравнения рядом с соответствующими счётчиками. В тесте двойной отправки задержанный ответ удерживается до конца попыток отправки. Так проверка не зависит от случайной продолжительности запроса.
