# Недельный отчёт GitHub

Сопровождающий репозитория выбирает понедельник и получает сводку за семь календарных дней. Источник первой версии — `nullifierx1/n8n-code-review-test`. Интервал между датами считается по UTC.

- До первого запроса видны репозиторий, подписанное поле даты и кнопка «Показать отчёт».
- Пустое поле, день, отличный от понедельника, и год вне диапазона 2008–9998 дают ошибку у поля. Запросов нет.
- Во время запроса виден статус загрузки. Повторный клик и Enter оставляют один запрос.
- Ответ показывает период и четыре счётчика: созданные и закрытые Issues, созданные и объединённые PR. Разбивки относятся к созданным Issues. Сравнение доступно при наличии данных прошлой недели.
- Четыре нулевых счётчика дают сообщение о пустой неделе. Отсутствующее сравнение обозначается отдельно.
- При ошибке дата сохраняется, пользователь может исправить её или отправить форму снова.

## HTTP

`GET /api/weekly-report?weekStart=YYYY-MM-DD`. Интерфейс работает через Vite-прокси. Целевой n8n Webhook возвращает один JSON-объект.

```json
{
  "weekStart": "2026-11-16",
  "weekEnd": "2026-11-22",
  "counts": { "openedIssues": 8, "closedIssues": 4, "openedPrs": 7, "mergedPrs": 1 },
  "byType": [{ "label": "bug", "count": 2 }],
  "byAuthor": [{ "label": "nullifierx1", "count": 8 }],
  "comparison": { "openedIssues": 8, "closedIssues": 4, "openedPrs": 7, "mergedPrs": 1 }
}
```

`comparison` содержит разницу с предыдущей неделей или `null`. Для пустых разбивок используются массивы. Любой HTTP-ответ с ошибкой или сбой сети показывается как ошибка загрузки. Веб-запрос возвращает данные для чтения.
